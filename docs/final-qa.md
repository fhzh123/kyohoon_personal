# 최종 HTTP·정적 접근성 검토

실제 담당은 내장 Codex 보조 에이전트입니다. 요청된 Antigravity 모델이나 앱을 실행하지 않았습니다.

## 수행한 검사

`node --test tests/public-http.test.mjs`를 실행하여 6개 검사를 통과했습니다. Node HTTP 서버를 loopback 임의 포트에서 실제로 열고 HTTP 응답을 확인했습니다. 테스트는 독립적으로 서버를 시작·종료하므로 개발 서버에 의존하지 않습니다.

- `/`, `/resume`, `/resume/`, `/work`, `/work/` 직접 요청: HTML 200 응답.
- 메인 전체 선택 영역: 이미지·제목·설명 전체가 두 개의 일반 링크 안에 있고 `/resume`, `/work`로 연결됨. 이미지가 제목보다 먼저 위치하며 접근 가능한 이름 연결이 있음.
- 메인·로그인의 PNG, CSS, 글꼴 요청: 200과 올바른 MIME 확인. PNG 시그니처·정사각형 비율·RGBA 형식 확인.
- Resume는 독립 HTML 문서이며 메인 CSS와 iframe을 사용하지 않음. HTML이 참조하는 Resume JS·CSS·아이콘·manifest 경로가 모두 200 응답.
- Supabase 미설정 Work 화면: 명확한 연결 전 안내, 이메일·비밀번호 label과 autocomplete, 비활성 로그인, 홈 링크 확인. 공개 회원가입 및 프로덕션 미리보기 링크 없음.
- 비로그인 상태에서 보호된 연구일지 HTML·스크립트·첨부·데이터 API는 401 및 no-store. `/work` 자체는 로그인 HTML을 200으로 응답함. 프로젝트 private/source/환경 파일/원본 Assets는 공개 경로로 요청 시 404.
- 현재 작업 사본이 있을 때 연구 제목 하나를 로그에 출력하지 않는 누출 감지 기준으로 사용하여 공개 HTML·CSS 응답에 포함되지 않음을 추가 확인함. private 데이터 없는 새 checkout에서도 테스트가 실행되도록 처리함.

## 정적으로 확인한 반응형·가독성 규칙

메인 CSS에서 760px 이하 단일 열, 유동 이미지, 한글 본문 줄바꿈, focus-visible, hover·active 피드백 및 prefers-reduced-motion 규칙을 확인했습니다. Work CSS에는 900px 사이드바 축소와 640px 가로 메뉴 전환, 타임라인 전용 스크롤, 긴 제목 `overflow-wrap:anywhere`, focus 및 움직임 줄이기 규칙이 있습니다.

Work 모바일 헤더는 기존 고정 높이와 새 홈·로그아웃 버튼의 조합 때문에 줄바꿈 시 겹칠 가능성이 있어 총괄에게 높이 자동 조절을 제안했습니다. 이후 `integration.css`에서 680px 이하 자동 높이·최소 높이·줄바꿈·검색 입력 최소 너비 처리가 반영된 것을 정적으로 재확인했습니다. 실제 화면에서 관찰한 결함이나 시각 재검증으로 보고하지 않습니다.

## Draft 추가 후 Work 허브 검증

이후 사용자가 `Assets/Draft/초기구상_1`의 Markdown과 PDF를 추가했습니다. 이 담당자는 Markdown에서 업무용 버튼 6~7개, 첫 세 항목 연구일지·Ontology 연구 데모·Document Parsing 연구 데모, 나머지 공사 중 표시 요구를 확인했습니다. Draft의 임시 인증 정보는 테스트·로그·문서에 복사하지 않았습니다. 인증은 상위 사용자 지시인 Supabase 이메일·비밀번호 방식으로 유지됩니다. PDF 시각 검토는 별도 담당자의 기록을 참조해야 하며 이 담당자가 수행한 것으로 보고하지 않습니다.

`tests/hub.test.mjs`의 5개 추가 검사는 합성 저장본을 사용하는 실제 loopback HTTP로 확인했습니다.

- 비로그인 `/work`에는 로그인만 보이고 두 외부 데모 제목·주소와 업무 실행 슬롯이 노출되지 않음.
- 허용된 localhost 미리보기는 `/work` 허브로 이동. 허브에는 실제 링크 3개와 비활성 공사 중 슬롯 4개가 표시됨.
- 연구일지는 `/work/app/index.html`, 두 외부 데모는 Draft의 정확한 URL이며 새 창·noopener·noreferrer 속성 적용. 실제 외부 데모 사이트는 방문하지 않았음.
- 홈·로그아웃과 로컬 저장 사본 상태 표시, 로그인 비밀번호 문의 mailto, 공개 회원가입 부재 확인.
- 프로덕션에서는 로컬 플래그와 다른 개발 세션 쿠키를 전달해도 미리보기 404 및 비로그인 허브 비노출.
- 기존 메인의 두 이미지 우선 선택 영역 유지.

기존 보안 테스트의 로그인 성공 후 목적지만 `/work/app/index.html`에서 Draft 기반 `/work` 허브로 갱신했습니다. 이 변경은 실제 최종 탐색 구조를 반영한 것입니다.

## 수행하지 못한 검사

브라우저 연결 호스트가 없고 Firefox 네이티브 접근은 도구 승인 시간 초과였습니다. 승인 우회나 다른 브라우저 자동화를 시도하지 않았습니다. 따라서 데스크톱·모바일 렌더링, 실제 focus 이동·터치·hover, 스크린샷, 픽셀 단위 Resume 비교를 완료했다고 주장하지 않습니다. HTTP·정적 검사와 다른 담당자의 DOM 시뮬레이터 검사는 실제 브라우저 시각 검증을 대체하지 않습니다.

Draft Markdown의 업무 허브 요구는 위와 같이 대조했습니다. 실제 Supabase·RLS·Storage·Vercel 연결 검증은 수행하지 않았습니다.
