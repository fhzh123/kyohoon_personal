# 접근 제한 검증

검토 담당은 실제 Antigravity가 아닌 내장 Codex 대체 담당이다. 브라우저 검증과 분리해 서버 핸들러의 권한 제어를 검사했다.

## 실행 결과

2026-11-11, 프로젝트 루트에서 실행:

```sh
node --test tests/security.test.mjs
```

**19개 검사 통과, 실패 0개.** 실제 Supabase에 접속하지 않고 주입한 가짜 응답으로 인증 분기를 검증했다. 요청·응답은 Node 스트림과 응답 객체로 구성해 실제 `createHandler`를 호출한다. 따라서 이 결과는 실제 배포·브라우저·외부 DB 연동 검증을 의미하지 않는다.

모든 파일 저장 검사는 `artifacts/security-fixture/case-*` 아래의 합성 자료로 수행했다. 실제 `private/work` 자료와 읽기 전용 업무 원본은 수정하지 않았다. 테스트 사본에는 실제 연구 내용이 없다.

## 코드 검토와 남은 확인

- 업무 파일을 읽기 전에 서버가 요청을 인증하는 순서를 확인했다.
- 로컬 쓰기 큐 내부에서 revision을 검사해 동시 저장 덮어쓰기를 막는 것을 합성 파일로 확인했다.
- 실제 이메일·비밀번호 로그인, Supabase RLS SQL 적용, Storage 권한, 허용 계정 간 권한 분리, 토큰 갱신의 외부 서비스 동작은 **미연결 상태**다. 사용자 설정 후 실제 Supabase에서 별도로 확인해야 한다.
- 실제 Vercel 배포는 수행하지 않았다. 배포 핸들러가 로컬 미리보기를 켜지 않는다는 코드 분기를 검사했으며, 배포 후 HTTP 검사까지 완료했다는 의미는 아니다.
- 타입 검사는 별도의 빌드 단계다. 현재 타입 검사 대상은 보안 정책 함수와 업무 상태 계약이며 서버 전체를 TypeScript로 검사한 것은 아니다.
- 보완 제안은 총괄에게 전달했다: Origin 검사에서 스킴까지 엄격히 비교할지 검토하고, preview·첨부파일 경로의 허용 메서드를 GET/HEAD로 명확히 제한하는 항목. 이 문서는 총괄의 후속 수정 완료를 주장하지 않는다.
