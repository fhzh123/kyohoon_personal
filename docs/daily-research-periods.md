# 연구 기간 일 단위 선택

연구의 시작일과 종료일을 달력에서 하루 단위로 선택한다. 주별, 월별, 연도별 로드맵은 그대로 제공하며 보기 단위가 저장 날짜를 변경하지 않는다.

- 시작일과 종료일 버튼을 누르면 작은 달력이 펼쳐진다. 선택한 양 끝과 사이 날짜를 구분하고 총 일수를 표시한다. 적용 전 선택은 임시 상태이며 취소하거나 Escape를 누르면 기존 기간을 유지한다.
- 같은 날 시작하고 끝나는 연구와 월을 넘는 기간을 지원한다. 월 이동, 방향키, Home/End, PageUp/PageDown으로도 날짜를 선택할 수 있다.
- 기존 연구 날짜는 그대로 보존한다. 수정하거나 이동한 일정은 `planUnit: day`로 저장하고 주, 월, 연 경계에 맞춰 늘이지 않는다.
- 일정 막대와 양 끝 조정도 일 단위로 처리한다. 상위 기간을 같은 일수만큼 이동하면 하위 연구도 같은 일수만큼 이동한다. 길이만 변경할 때 하위 기간은 유지한다.
- 상위 기간을 세부 기간에 맞추는 기능도 정확한 시작일과 종료일을 사용한다. 실제로 상위 기간을 벗어난 연구의 경고는 유지한다.
- 브라우저 저장, 기존 공유 저장 API, 읽기 전용 권한을 유지한다. 데이터베이스 스키마 변경이나 일괄 데이터 갱신은 없다.

## 검증

프로덕션 빌드 성공. 연구 기능, DOM 통합, 원본 가져오기 검사 53개 통과. 기존 날짜 보존, 범위 선택, 동일 날짜, 역순 선택, 취소, 키보드 이동, 읽기 전용 권한, 일 단위 이동과 기간 조정, 하위 연구 동반 이동, 주/월/연 보기 전환을 검증했다. 공유 저장 검사는 모의 API를 이용한다.

날짜를 선택하면 달력이 다시 그려져 클릭한 버튼이 DOM에서 교체된다. 바깥 클릭 검사가 교체 후의 `contains(event.target)`를 사용해 내부 날짜 선택을 바깥 클릭으로 오인하고 임시 선택을 닫던 오류를 수정했다. 원래 이벤트 경로인 `event.composedPath()`로 내부 클릭 여부를 판정한다. 시작일과 종료일 선택 후에도 달력과 적용 버튼이 계속 보이는지, 실제 바깥 클릭은 임시 선택만 취소하는지 재현 검사했다. 개별 스크립트로 시작하는 경로에도 달력 모듈을 포함했다.

전체 테스트에서 발견한 기존 홈페이지, 이력서, 로그인 기대값 불일치는 변경 전 원본에서도 재현된다. 이번 작업의 변경 범위에 포함하지 않았다.

`GATE: ERROR` — 환경에서 Chrome이 실행되지 않아 consistency와 layout 검사 및 화면 캡처를 완료하지 못했다. 실제 브라우저의 모바일 배치, 다크 모드, 글꼴과 포커스 표시를 시각적으로 검증했다고 간주하지 않는다. 새 달력은 기존 색상 토큰과 글꼴을 사용하며 동작 감소 설정을 지원한다.
